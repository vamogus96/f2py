# Licensing guide for Hollow Lullaby

> **Not legal advice.** This is an engineering summary to help you decide and document. For a commercial release, have a lawyer review it.

## 1. What is in the project today

| Part | Origin | Licence | Action needed |
|---|---|---|---|
| `game.js`, `day.js`, `naval.js`, `server.js`, `index.html` | Written for this project | **Not yet chosen** | Pick a licence (section 3) |
| `WORLD.md`, `README.md`, `UE5_TUTOR_ROADMAP.md` (story, text) | Written for this project | **Not yet chosen** | Same decision, possibly a separate one for the story and text |
| Textures, 3D models, audio | Generated by code at run time | Part of the code | None. No third-party assets are bundled |
| `three.min.js` | three.js r160 | MIT | Keep the notice: done in `THIRD_PARTY_NOTICES.md` |
| `ws` (npm) | ws 8.x | MIT | Notice kept in `THIRD_PARTY_NOTICES.md` |
| Repo-root `LICENSE` | The f2py project (Pearu Peterson, BSD-style) | BSD-style | Covers the f2py code. It does not say what applies to the unrelated `dream-horror/` folder, so add a licence file inside the folder |

Things that are **not** copied: code, art or audio from Hotline Miami, Superhot, Papers, Please or Unreal Engine. The README names them only to describe the mechanics that inspired the modes (ideas and mechanics are generally not protected by copyright, but names, logos and trade dress can be). Do not use those names in the product title or store page.

## 2. Direction of dependency (this matters)

- **Incorporating** MIT libraries (three.js, ws) **into** your game: allowed under any licence you choose for your own code, including proprietary and commercial. You must keep their copyright and permission notices (done).
- **Releasing** your game under licence X: X only has to be compatible with the licences of what you ship. MIT is compatible with almost everything.
- If you later add Apache-2.0 code: it is compatible with GPL-3.0 but **not** with GPL-2.0-only. If you add GPL or AGPL code, the combined game may have to be released under that licence.

## 3. Choosing a licence for your own code

| | MIT | Apache-2.0 | GPL-3.0 | AGPL-3.0 | All rights reserved (proprietary) |
|---|---|---|---|---|---|
| Others may use it commercially | Yes | Yes | Yes | Yes | No (needs your permission) |
| Patent grant | No | **Yes** | Yes | Yes | n/a |
| Copyleft / share-alike | No | No | **Yes** (distribution) | **Yes** (also over a network) | n/a |
| Can be sublicensed into closed-source products | Yes | Yes | No | No | By agreement |
| Notice file required (`NOTICE`) | No | If you ship one | No | No | n/a |
| Relevant to the online relay (`server.js`) | Fine | Fine | Network use does not trigger copyleft | **Hosting a modified relay triggers source sharing** | Fine |

Rule of thumb: **MIT or Apache-2.0** if you want maximum reuse and don't care about forks; **GPL-3.0 or AGPL-3.0** if you want improvements shared back; **all rights reserved** if you plan to sell it and keep the source. You can license code and creative content differently (for example code under MIT, story and art under CC BY-NC 4.0).

## 4. Ready-to-use templates

Templates with `[PLACEHOLDERS]` are in `docs/license-templates/`:

- `MIT.txt`: copy to `dream-horror/LICENSE` and fill in the year and holder.
- `SPDX-header.txt`: a one-line header for source files.
- `package.json`: once you have chosen, add `"license": "MIT"` (or the SPDX id you chose; `"UNLICENSED"` if proprietary).

## 5. Automatic checking

`scripts/check-licenses.js` (run with `npm run check:licenses`) fails when:
- a production dependency has a licence outside the allow-list (MIT, ISC, BSD-2/3-Clause, Apache-2.0),
- a dependency in `package.json` is missing from `THIRD_PARTY_NOTICES.md`,
- the vendored `three.min.js` has lost its MIT header.

It only **warns** while no project `LICENSE` exists yet. The GitHub Action `.github/workflows/license-check.yml` runs it on every change under `dream-horror/`.

## 6a. Trademarks and real names (important for the Tower raid)

The Turin tower is called the **Arasaka Tower** and is described as the former **Intesa Sanpaolo** skyscraper. Both names are used as in-fiction labels:
- *Intesa Sanpaolo* (the bank and its tower) is a registered trademark of Intesa Sanpaolo S.p.A. The Tower raid shows armed security guards and a villainous chairman in a building named after a real bank. That is satire in a fictional world and names no real person, but it can still be objected to, especially in a commercial release.
- *Arasaka* belongs to the *Cyberpunk* franchise of CD Projekt S.A. A fan game that borrows the name is not licensed by them.
- The combat rules are inspired by the *Hotline Miami* genre. Rules and mechanics are generally not protected, but its **names, art, music and level layouts are**: this game uses none of them.

Before a public release: rename the tower and the bank (one string each: `Arasaka Tower` in `day.js`, `hotline.js`, `WORLD.md`), or get permission. Not legal advice.

## 6. Other compliance points

- **Multiplayer relay:** it relays player names and positions in memory only and stores nothing. If you host it publicly, tell players what is processed and consider a short privacy notice (names are user-supplied, so avoid real names).
- **Save data:** the game stores progress (skills, parts, tutorial flag) in the browser's `localStorage` on the player's own device.
- **Trademarks:** check availability of the title "Hollow Lullaby" before a commercial release.

## 7. Suggested next steps

1. Choose a licence from the table above; copy the matching template to `dream-horror/LICENSE`.
2. Add the SPDX header to the source files (a one-line script can do this).
3. Update `package.json` with the licence id.
4. If you ever bundle third-party art or audio, add each one to `THIRD_PARTY_NOTICES.md` with its licence and source URL.
